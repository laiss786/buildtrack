## Step 2: Add patch import to dashboard.html

At the very **end** of your `<body>` in `dashboard.html`, add:

```html
<!-- After the existing dashboard.js script tag -->
<script type="module" src="js/dashboard-patch.js"></script>
```

That's it. The patch auto-wires everything.

## Step 3: Get your Anthropic API key

The AI report uses Claude to write reports.

1. Go to → https://console.anthropic.com
2. Create an API key
3. Add it to your Firebase project as an environment variable OR add it directly to `ai-report.js` in the fetch headers:

```js
headers: {
  "Content-Type": "application/json",
  "x-api-key": "YOUR_API_KEY_HERE",       // ← add this line
  "anthropic-version": "2023-06-01",
  "anthropic-dangerous-direct-browser-ipc": "true"
}
```

> **Security note:** For a final year project demo, putting the key directly in the JS is fine.
> For production, proxy the API call through a Firebase Cloud Function so the key stays server-side.

## How Each Feature Works

### 1. Offline Mode with Auto-Sync

**What's saved offline:**
- Daily site journal entries
- Material stock additions
- Attendance records (all workers for a date)

**How it works:**
1. When offline, an amber banner appears at the top: *"You're offline — changes saved locally"*
2. A pending count badge shows how many changes are waiting
3. The user fills in forms exactly as normal — data is saved to **IndexedDB** in the browser
4. The moment internet returns, changes automatically sync to Firestore
5. A green toast confirms: *"3 offline changes synced to cloud ✓"*

**Data stored in:** `IndexedDB → buildtrack_offline → pending_writes`

**Offline-capable sections:** Daily Logs, Materials (add stock), Attendance (save button)

---

### 2. AI Site Report Generator

**Where it appears:** Reports section → top of page, above existing report cards

**How to use:**
1. Go to **Reports** in the sidebar
2. Select a project (or leave as "All Projects")
3. Pick the week-ending date
4. Click **Generate AI Report**
5. The AI fetches:
   - All daily journal entries for that week
   - Attendance records + labourer wage calculations
   - Material transaction logs
   - Expenses recorded that week
6. Claude writes a professional 6-section report in ~5 seconds
7. You can **Copy**, **Download as .txt**, or **Send via WhatsApp**

**Report sections generated:**
1. Weekly Summary
2. Work Progress (from journal entries)
3. Labour & Attendance (rate, absences, total cost)
4. Material Usage (received vs consumed)
5. Financial Snapshot (expense breakdown)
6. Issues & Recommendations

---

### 3. WhatsApp Weekly Report

**How it works (no API key needed — uses wa.me):**

1. After generating an AI report, click **Send via WhatsApp**
2. A WhatsApp panel slides open with a preview of the message
3. Enter the contractor's WhatsApp number (with country code, e.g. +91 98765 43210)
4. Click **Open WhatsApp** — this opens WhatsApp with the message pre-filled
5. The contractor just hits Send

**Message includes:**
- Week ending date + project name
- Attendance summary (present/total)
- Labour cost for the week
- Total weekly spend
- AI-written summary excerpt
- "Generated by BuildTrack" footer

**Why wa.me instead of the API?**
- No business verification needed
- No paid plan required
- Works immediately
- Perfect for a project demo

**To upgrade later to WhatsApp Business API:**
- Use Twilio's WhatsApp sandbox (free for testing)
- Or apply for Meta WhatsApp Business API access

## Background Sync (Bonus)

The updated `service-worker.js` registers for the **Background Sync API**.
On supported browsers (Chrome Android), if the user submits a form and immediately loses connection,
the service worker will automatically retry the sync even after the tab is closed.

To enable it, add this to your `dashboard-patch.js` after saving an offline record:

```js
if ("serviceWorker" in navigator && "SyncManager" in window) {
  const reg = await navigator.serviceWorker.ready;
  await reg.sync.register("buildtrack-sync");
}
```

The service worker sends a `BACKGROUND_SYNC_TRIGGERED` message to all open clients,
which triggers `syncPendingWrites()` in `offline-sync.js`.

## Testing Offline Mode

1. Open Chrome DevTools → Network tab → set to **Offline**
2. Fill in a daily log entry and submit
3. You'll see the amber offline banner and the entry appears with "⏳ Pending sync" badge
4. Switch Network back to **Online**
5. The sync runs automatically — the pending badge disappears and a green toast appears

## FAQ

**Q: Does offline mode work on iOS?**
A: Yes — IndexedDB is supported on Safari iOS 13+. The offline banner and sync both work.

**Q: What if the same data is submitted twice (once offline, once online)?**
A: Each offline entry gets a unique local ID. Attendance records use `labourerId_date` as the document ID (idempotent `setDoc`), so duplicates are safely overwritten.

**Q: Can I use a different AI model?**
A: Yes. In `ai-report.js`, change `"claude-sonnet-4-20250514"` to any supported model string.

**Q: Does the WhatsApp message get sent automatically?**
A: No — it opens WhatsApp with the message pre-filled. The user taps Send. This avoids needing the paid Business API.
